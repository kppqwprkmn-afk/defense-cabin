## 旁白全文

### 01 痛点（00:00）

每年答辩季，都有一些项目，明明做了很多工作，却在台上被三个问题问住。你的准确率，跟谁比？你的样本，是怎么选的？这个百分之六十，是目标还是结论？问题往往不在表达能力，而在于，从来没有人，真的按评审的口径，逐条追问过你。同学不好意思下狠手，导师时间有限，现有的 AI 工具，只会总结和润色。答辩预演舱，就是为此而生。它把三位 AI 评审请进你的电脑，让你先被问倒，再上战场。

### 02 上传与解析（00:41）

第一步，上传你的申报书。PDF、Word、Markdown 都可以。系统不会做一份泛泛的摘要，而是把材料拆成一条一条，可以被质询的论点。每一条都标出类型、证据强度，和七类缺口：缺基线、缺样本、因果混淆、承诺性指标、没有出处。左边是材料体检，八个评审必看板块，哪些有、哪些缺，一眼就能看到。右边是论点清单，十二个最容易被问住的地方，已经按优先级排好。这不是让你自我感觉良好，而是先把最疼的地方找出来。

### 03 交叉质询（01:24）

三位评审，三种下刀方式。方法学教授沈砚，只关心你的实验能不能站住。他会问：这个数字的基线是什么？同数据集、同参数量、同标注规范的对照，有没有？产业评委罗启，关心谁付钱。部署、标注、运维、换件，这一整套，单间全生命周期成本是多少？竞赛评审周律，按评分表逐条对照：专利是受理还是授权？复现材料里，权重和数据在哪里？点击开始，质询正式开始。每一个问题，都绑定材料里的一句原话。点开证据，你能看到原文、章节，和检索相关度。答辩人由你的材料驱动，它只知道你写过的东西。所以它露怯的地方，就是你材料真正的缺口。

### 04 报告（02:26）

注意右栏。风险不是最后才出现，而是在质询过程中，一条一条长出来。这一场，系统识别出六条风险，其中五条是高危。证据强度只有六十分，合规与复现六十一步。报告不会只给一个分数。它给出五维雷达、风险清单，和按 P0、P1、P2 排序的修改清单。每一条，都带关联论点、工作量和预计提分。比如，先补基线对照与置信区间，再做归因拆解，最后补样本分层。这是一张明天就能开工的施工图，而不是一句正确的废话。

### 05 AI 协同复现（03:10）

接下来，是这两分钟，也是这个作品最重要的部分：它是怎么做出来的。这不是一次性生成的代码。我们保留了五次关键的推翻。第一，把赛题收敛。没有做通用 Agent 平台，而是锁定答辩这一个高 stakes 场景。第二，材料解析。第一版把所有句首年份都当成列表序号，二零二五年九月，变成了年九月。我们收紧正则，只处理一到两位数字加顿号的列表标记，并加了一条单测，确保年份原样保留。第三，多 Agent 编排。最初的 SSE 会丢消息，因为 POST 已经开始推流，EventSource 才建立；刷新还会重复，因为前端无条件插入。修复方式是先订阅再重放，前端按 turn id 去重，turn end 覆盖流式占位。第四，评分校准。第一版给示例项目六十六分，证据强度四十二，还有三条同名风险和三连 P0。我们把单维扣分封顶十六分，按标题去重，让它回到七十一分。仍然锋利，但不再失控。第五，可复现构建。Windows 下 pnpm 的 junction、esbuild 双版本、失效的 .bin，三个问题叠加。最终用 hoisted 安装和直接 node 入口，让评委可以一条命令跑起来。每一次 Prompt、每一个报错、每一次修复，都在 docs prompts 和 Git 历史里。七个单元测试，一条端到端链路，二十多次细粒度提交，构成了它的可复现底座。我们相信，Vibe Coding 的竞争力，不是谁生成得更快，而是谁能在 AI 的洪流里，保持架构判断、证据意识和可复现的工程纪律。这个作品，就是一次公开的证明。

### 06 收束（05:13）

先被问倒，再上战场。答辩预演舱，把答辩风险，提前暴露在材料里。现在，轮到你了。
