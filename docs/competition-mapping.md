# 评审标准对标

> 赛题评分：过程可复现 25%、实用价值 25%、方法创新 20%、工程质量 15%、用户体验 15%。

## 1. 过程可复现性与演进链路（25%）

| 评审会看什么 | 本作品的证据 | 在哪 |
| --- | --- | --- |
| Git 历史是否细粒度、非一次性提交 | 20+ 次提交，按 scaffold → domain → engine → API → UI → fix → docs → test 分层 | `git log --oneline --reverse` |
| Prompt 历史是否完整 | 5 个核心迭代，含指令、AI 产出、翻车、修复、验证 | `docs/prompts/` |
| Bug 是否真实、修复是否可追踪 | 年份被正则吃掉、SSE 丢消息/重复、评分 42/三连重复、pnpm/esbuild 冲突 | `docs/prompts/02~05` |
| 评委能否一键复现 | `pnpm install && pnpm build && pnpm start`，无 Key、无数据库 | README 第 3 节 |
| 代码是否拼接 | 统一类型、单一 store、无复制粘贴的页面模板；测试覆盖核心算法 | `packages/shared`、`apps/server/src` |

**演示动作**：打开 `/making-of`，从 01 滚到 05；再切到终端 `git log --oneline` 对照。

## 6. 可能被追问的点（提前准备）

1. **“这不就是让 GPT 扮演评委吗？”**  
   不是。结构由确定性剧本决定，LLM 只润色台词；没有 Key 也能跑完整 27 轮。核心创新在“论点级证据绑定 + 可回放风险模型”。

2. **“评分凭什么可信？”**  
   评分是规则化的风险折算，不是模型打分；每个扣分项都能回跳到具体论点和材料原文。它是演练参考，不是奖项预测。

3. **“示例数据是编的吗？”**  
   是虚构的示例项目，明确标注；产品支持上传真实材料。演示用虚构数据是为了不暴露任何学校信息。

4. **“为什么不用向量库？”**  
   单文档、1–2 万字场景，BM25 足够且零依赖、可解释、可复现。规模上来后 `BM25Index` 可替换为 pgvector/Qdrant，接口不变。

5. **“AI 对话记录是真实的吗？”**  
   `docs/prompts/` 是本次开发会话的结构化还原，保留了真实指令、报错与修复；不是聊天工具逐字导出。若赛事要求原始导出，可用工具截图/录屏补充。
