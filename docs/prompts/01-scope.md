# Prompt 链 · 00 选题收敛

## 1. 人类输入（节选）

```text
全国高校 Vibe Coding 开发挑战赛……（完整赛题：10 个选题方向、提交要求、
评分维度：过程可复现 25%、实用价值 25%、方法创新 20%、工程质量 15%、
用户体验 15%）

要求：
1. 先不要写代码，判断你能否独自完成，哪些部分必须我来做；
2. 给出一个能在 5 分钟内演示清楚、同时覆盖“多 Agent + RAG + 高交互可视化”的选题；
3. 说明它如何对应评分表，而不是做一个泛泛的聊天机器人。
```

## 2. AI 的第一次判断

AI 没有直接开工，而是先做了三件事：

- 否定了“通用多 Agent 平台”这种大而空的方向：演示无法在 5 分钟内闭环，且容易沦为聊天框换皮。
- 给出了三个候选：答辩预演舱、教务规划器、Attention 可视化工坊。
- 推荐答辩预演舱，理由：
  1. 痛点是真实的、高 stakes 的（答辩失败成本高）；
  2. 天然适合多 Agent 交叉质询，角色冲突强，演示有张力；
  3. 材料是学生手头现成的申报书，不需要造数据；
  4. 风险雷达/修改清单构成完整产品闭环，能对应“实用价值 25%”。

同时明确列出 AI **不能代做**的部分：报名与组别、真实 API Key、选手本人的 AI 对话导出、本人视频旁白。

## 3. 人工收敛

人类确认：“完整可提交作品包” + “答辩预演舱”。  
产品边界被锁定为：

> 上传材料 → 抽出可质询论点 → 三位评审交叉质询 → 风险雷达 + 修改清单 → 再练一次。

不做：通用文档问答、自动写申报书、奖项预测、多人协作。

## 4. 为什么这一步重要

如果一开始就写代码，最容易做成“又一个 RAG 问答”。  
这一步把“AI 能做什么”翻译成“评委在 5 分钟内能看到什么”，后续所有工程决策都围绕这条演示链路展开。
