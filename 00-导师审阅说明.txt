二、作品一句话

答辩准备里最常见的问题，不是“没内容可讲”，而是材料里的弱证据平时没人逐条指出来。这个程序把“被追问”提前到答辩之前：每条追问都挂材料原文，每条风险都能回到具体论点，最后给出先改哪一条的顺序。

三、学生本人做了什么，AI 做了什么

这部分如实说明，便于老师判断原创性和工作量。

学生负责：
- 选题与场景收窄：否掉“通用 Agent 平台”，只做答辩这一个场景；
- 产品流程与交互：首页、材料预检、质询现场、报告、研发现场五个页面；
- 数据结构与约束：前后端共享类型，domain / engine / routes / store 分层；
- 验收与测试：单元测试、Playwright 端到端、真实 Bug 复现与修复；
- 文档、演示视频脚本、提交材料整理。

AI 编程助手参与：
- 代码生成、重构、重复页面搭建；
- Bug 定位建议、测试用例草稿；
- 部分文案和视觉方案的备选。

过程留痕：
- GitHub 仓库 35 次提交，作者均为学生本人账号；
- docs\prompts 保留 5 个阶段的 Prompt 演进；
- docs\test-report.md 记录真实 Bug、修复和测试结果；
- 视频里的“研发现场”页可直接看到五次迭代。

需要老师重点把关：
1. 选题价值：答辩预演是否是一个足够具体、真实的需求；
2. 评分模型：五维风险折算是否合理，是否存在“看起来精确但其实主观”的问题；
3. 原创性表述：哪些是学生设计，哪些是 AI 生成后由学生修改，文档中的说法是否恰当；
4. 演示与文档：有没有夸大效果，是否把“演练参考”说成了“结果预测”。

四、目前已知局限

- 默认使用确定性离线剧本，保证老师在断网环境也能复现；真实 LLM 是可选增强，不是必需。
- 评分是风险折算，不是奖项预测；报告里已写明“不构成评审结论”。
- 质询轮数是标准 27 轮、高压 31 轮，不是无限对话。
- 示例项目“智巡校园”是虚构材料，不涉及真实学校数据；产品支持上传真实材料。
- 移动端做到 390px 可用，但没有做原生 App。

六、怎么运行

方式一（推荐给老师）：双击根目录 `启动.bat`，等 3 秒，浏览器打开 http://127.0.0.1:8799。关闭黑色窗口即停止。

方式二：双击 `portable\start.bat`，效果相同。portable 内置 Node 运行时和依赖，不需要安装 Node、pnpm，不需要联网，仅限 Windows 64 位。

方式三（Mac / Linux）：按 README 使用 pnpm install、pnpm build、pnpm start，打开 http://127.0.0.1:8787。

注意：不要双击 apps\web\index.html，那是源码入口，会白屏。
